The two-beat cycle

After a one-off pure-VLA startup, every inference cycle is replan → rectify on one connection.

  1. Startup (t₀). No old chunk exists, so run the VLA once — a pure replan, no rectify — and begin executing chunk₀ from the front. This is the only cycle without a rectify.
  2. Replan on obs_old. The background thread sends the current observation and the frozen VLA runs (~tens of ms), storing stale_chunk + kv_cache for this connection. Control never blocks — it keeps popping the old chunk, so the joint moves continuously.
  3. Measure & compute delta. The instant replan returns, the client measures its latency and sets delta = max(2, ceil(latency × rate)) — the number of control steps the observation has drifted. Never hardcoded.
  4. Rectify on obs_new. Grab the freshest observation and run the lightweight RectifierDiT (~5 ms), reusing the stored stale chunk + kv over the same connection. The VLA does not re-run.
  5. Atomic swap. Replace current_chunk with the rectified chunk and reset the cursor to control_delay (default 0). No crossfade, no dropped frames — the corrected chunk is executed verbatim from the front.
